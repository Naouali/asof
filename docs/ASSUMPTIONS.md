# Assumptions

Where a requirement was ambiguous, the **most conservative** reading was taken —
the one that understates strategy performance — and recorded here. Each entry names
the milestone in which it was made so it can be revisited with context.

Correct anything here that is wrong for your purposes; these are defaults, not
convictions.

## Milestone 1 — skeleton and Docker

| # | Ambiguity | Choice made | Why it is the conservative one |
| --- | --- | --- | --- |
| 1 | Python version. The spec says 3.11+. | Images pin **3.12**; `requires-python = ">=3.11,<3.13"`. | 3.12 has complete wheel coverage for the scientific stack on both architectures. The upper bound prevents a silent jump to a version some dependency has not been tested against. |
| 2 | Dependency pinning granularity. | Ranges in `pyproject.toml`, **exact pins for all 176 packages in a committed `uv.lock`**, installed with `uv sync --frozen`. | `--frozen` refuses to update the lock, so an image can never be built from a resolution that is not the committed one. CI runs `uv lock --check` so the two cannot drift. |
| 3 | What an unimplemented command should do. | Exit **2** with the milestone named. | The alternative — returning an empty result — is indistinguishable from "ran fine, found nothing", which is exactly the failure mode spec section 13 forbids. |
| 4 | Whether to enable scheduled jobs before their code exists. | All jobs disabled except `doctor`. | An enabled job that exits 2 every night trains the operator to ignore scheduler failures. |
| 5 | Default `User-Agent`. | A string containing the literal word `unconfigured`. | `doctor` catches it before the SEC does. A plausible-looking default would get silently blocked at the first EDGAR request. |
| 6 | Whether missing API keys should block startup. | No. Every key is optional; `doctor` reports what is unavailable and why. | Spec section 10 requires the stack to run with zero keys. |
| 7 | Where paper-trading state lives. | Postgres + TimescaleDB, **never bulk market data**. | Keeps the DuckDB-over-parquet research path free of a database server, per spec 3.8. A test asserts no other database engine appears in the compose file. |
| 8 | Dashboard and Jupyter authentication. | No auth; both bound to `127.0.0.1` only. | Auth that is not audited is worse than a loopback binding that is obvious. A test asserts every published port starts with `127.0.0.1:`. If you ever change that binding, add a token. |
| 9 | Postgres exposure. | Not published to the host at all. | The default password is `quantlab`. An exposed Postgres with a default password is a real liability, not a theoretical one. The override example shows how to publish it deliberately. |
| 10 | How container health is determined. | Heartbeat files whose freshness is asserted, not PID liveness. | A deadlocked worker keeps its PID. A heartbeat check catches the case that matters. |
| 11 | `PYTHONHASHSEED`. | Pinned to `0` in the images and in CI; `doctor` warns when it is unset. | Unseeded hash randomisation varies set and dict iteration order, which is enough to change floating-point reduction order and break byte-identical results. |
| 12 | Scheduler timezone. | UTC, with market-local conversions deferred to the trading calendars. | A DST shift in a local-time cron would silently move a job across a data release. |
| 13 | Whether the data catalogue is documentation or code. | Code (`src/quantlab/data/catalogue.py`); `docs/DATA_CATALOGUE.md` is generated from it and CI fails if it is stale. | A hand-maintained caveat that has drifted is worse than no caveat: it is a false assurance. |
| 14 | pandas. | Permitted only in the `research` extra for interop; **banned in `signals/`, `backtest/`, `costs/`, `portfolio/`** by a ruff rule and by a test that ignores `# noqa`. | Spec section 13. Polars' lack of an implicit index makes silent time-misalignment much harder to write. |
| 15 | Source rate limits where the provider publishes none. | A conservative self-imposed throttle per source, recorded in the catalogue (0.2–8 req/s). | Being throttled or IP-banned mid-ingest corrupts a dataset in ways that are hard to detect later. |
| 16 | Exchange settlement scraping (the only free route to a futures curve). | Catalogued, throttled to 0.5 req/s, and **disabled by default** pending a terms-of-service review. | Automated access may be prohibited. This one needs a human decision, not a default. |

## Milestone 2 — data layer

| # | Ambiguity | Choice made | Why it is the conservative one |
| --- | --- | --- | --- |
| 17 | The spec's row contract is `as_of` + `ingested_at`. | Added a third column, **`known_at`**, and made it the point-in-time filter. `ingested_at` is kept for audit only. | Collapsing "when the world learned it" into "when we downloaded it" makes ALFRED vintages and SEC filed dates unusable — and those are the only genuine point-in-time data available for free. With one column, either historical macro backtests are impossible or they are dishonest. |
| 18 | What `as_of` means for a daily bar. | The **session close in UTC**, from the venue's trading calendar — not the session date. | A bar is not information until it has closed. A bare date makes a Tokyo close and a New York close on the "same date" look simultaneous when they are fourteen hours apart. |
| 19 | What a bare `date` means at a query boundary. | `start` widens to 00:00:00, `end` and the snapshot instant to 23:59:59.999999, all UTC. | If both widened to end-of-day, `scan(start=T, end=T)` would return nothing — a silently empty result, the exact failure this platform exists to prevent. End-of-day for the snapshot matches the spec's rebalance convention (signal on the close of T). |
| 20 | Whether an unknown exchange should default to a US calendar. | Raise `UnknownVenueError`. | Guessing a venue's hours misaligns every bar of that instrument by hours. It never raises and it always flatters. |
| 21 | Whether FRED may be used for any series. | **No.** Every series must be explicitly classified in `SERIES_POLICY` as never-revised (FRED, with a publication lag) or revised (ALFRED only). An unclassified series raises. | Pulling `GDPC1` from FRED yields a beautiful macro signal and no clue why it fails live. Forcing the classification makes the decision visible in a code review. |
| 22 | Yahoo's `adj_close` and raw prices. | Stored, and documented as restated. Total returns are to be built from `close` plus the `corporate_actions` dataset. | Yahoo restates prices for splits that happen *later* — a May 2014 Apple close is served divided by 28, covering a split six years after the bar. Returns are unaffected; price-level signals are wrong and nothing raises. |
| 23 | Stooq now serves a JavaScript proof-of-work anti-bot challenge instead of CSV. | **Do not solve it.** Detect the interstitial, fail loudly, disable the job in the shipped plan, and record the lost cross-check in LIMITATIONS.md. | It is an access control the operator deliberately deployed. Defeating it is a terms-of-service problem and gets the IP banned mid-ingest. Yahoo becomes the primary equity source and its adjustments are now unverified by an independent party — which is a real cost, stated rather than hidden. |
| 24 | How incremental ingest resumes. | From the newest `as_of` already in the lake, minus a per-job overlap window. No cursor file. | A cursor file is state that can disagree with the data it describes. The data cannot disagree with itself. The overlap is free because partition filenames are content-addressed. |
| 25 | Whether arbitrary SQL should be available to signals. | Only inside `Snapshot.sql`, on a DuckDB connection built with `enable_external_access=false` holding pre-filtered tables. | DuckDB refuses to re-enable access at runtime, so no query — however written — can reach the lake files and read around the point-in-time filter. Verified by the leakage suite. |
| 26 | Yahoo intermittently caps history at 20 years and reports `firstTradeDate` to match, so truncation is undetectable in-payload. | Request in 8-year windows (helps sometimes), verify coverage against the trading calendar, and warn when a fetch returns less history than the lake already holds. Do **not** fail the run. | Failing would make ingest unusable, since the cap is intermittent and the append-only lake means a re-run recovers the missing span. The honest cost — a first ingest can silently be short — is documented in LIMITATIONS.md with the instruction to check `data status`. |
| 27 | Whether unit tests may touch live APIs. | No. A transport-level block fails any unmarked test that opens a socket; live calls require `@pytest.mark.network`. | A test that silently hits a live API depends on a third party's uptime and on today's market data, and starts failing for reasons unrelated to the code. |

## Milestone 3 — cost models

| # | Ambiguity | Choice made | Why it is the conservative one |
| --- | --- | --- | --- |
| 28 | Calibration of the square-root law. The spec gives Y in 0.5–1.0 and δ in 0.4–0.7. | **Y = 0.5, δ = 0.5** for equities, with per-asset-class overrides (FX 0.3, futures 0.4, crypto 0.8, credit 1.0). Both configurable. | Y = 0.5 with 2% daily volatility puts a 1%-of-ADV order at 10 bp, which matches the practitioner rule of thumb. The per-class spread reflects real depth differences; credit is set at the top of the range and should still be treated as optimistic. |
| 29 | How much of the peak impact a trade actually pays. | Temporary in full, **half** the permanent. | Permanent impact accrues while the order is worked, so early fills execute before most of it has happened. This is standard Almgren-Chriss implementation-shortfall accounting for a uniform schedule; a front-loaded schedule pays more. |
| 30 | Whether permanent impact depends on execution speed. | **No.** Only the temporary component responds to urgency. | Permanent impact reflects the information and inventory the trade reveals, not the rate. Making it speed-dependent would imply you can avoid it by trading slowly, which is the one thing execution cannot do. |
| 31 | Behaviour beyond ~10% of ADV, where published fits thin out. | Compute the number, flag it, and label any capacity resting on it an **upper bound**. | The law is known to *understate* impact beyond its calibrated range, so a capacity that requires 70% of a name's daily volume is a ceiling, not an estimate. Refusing to compute it would be unhelpful; computing it silently would be dishonest. |
| 32 | Almgren-Chriss units. | The whole problem is dimensionless: quantities are participation, coefficients are price-fractions per unit participation rate. | It lets the coefficients be derived from the calibrated empirical law rather than from a second, independent calibration — and makes the risk-neutral solution reproduce the square-root law exactly, which is asserted by test. A share-based formulation made risk aversion silently inert. |
| 33 | Low-frequency spread estimators are upward-biased, and the spec forbids using them uncritically. | Implement the correction **machinery** with an explicit factor, tick floor, cap and provenance string. Default to **no shrinkage**, flagged as uncalibrated. Provide `calibrate_correction` to fit the factor from observed quotes. | A shrinkage factor copied from a paper's sample period into your universe is a guess wearing a citation. No shrinkage overstates cost and understates capacity — the error this platform prefers — and the platform can genuinely calibrate, because crypto gives free ground truth. Measured on simulated data with a known 20 bp spread: Roll +379%, Corwin-Schultz +250%, Abdi-Ranaldo −6%. Abdi-Ranaldo is therefore the default. |
| 34 | What to do when Roll or Corwin-Schultz is undefined, which is often. | **Raise**, and report `coverage` — the share of windows that produced an estimate. | The original papers set negatives to zero. Doing that silently converts "no information" into a confident claim of a free round trip, and it is the specific practice spec section 5 warns against. A Roll estimate of 1e-12 bp arrived at by floating-point accident is rejected for the same reason. |
| 35 | Short borrow fee when unknown. | **15 bp/month (180 bp/year)**, and the assumption is flagged all the way to the tearsheet. | Spec section 5 names 10–20 bp/month as the range that erases most published anomaly alphas. This is the single most consequential default in the package: a long/short equity strategy's net alpha is roughly linear in it. |
| 36 | Interest earned on short sale proceeds. | **Zero** by default. | Most accounts earn none of it. Assuming otherwise manufactures a risk-free income stream, and the flattery is proportional to the rate environment — so it appears exactly when the strategy looks best. |
| 37 | Day-count for financing accruals. | **ACT/365.** | ACT/360 would understate every financing charge by 1.4%. |
| 38 | Whether a flat basis-point model should exist at all. | It exists, but `FlatBpsCostModel` refuses construction without `acknowledge_unrealistic=True` and logs a warning. | Spec section 13 forbids it as a *default*, not as a teaching tool. Being able to show on a tearsheet that a flat 10 bp assumption understates a real order by several multiples is worth more than pretending the option does not exist. |
| 39 | Low-frequency spread estimators proved catastrophically wrong on real liquid crypto bars (167 bp estimated against a 0.001 bp true spread), not merely biased. | Report a **resolution floor** (`σ/√n`) with every estimate; mark estimates inside their own noise as untrustworthy; carry a `spread_source` provenance field on every instrument; and warn when a crypto instrument is costed from an estimate rather than an observation. | The failure is invisible without ground truth, and ground truth exists for exactly one asset class. Making provenance explicit means a capacity number can say how much of itself is measurement and how much is assumption, instead of both looking identical. |
| 40 | Reporting capacity for a strategy whose costs exceed its edge at any size. | Return **no capacity** with an explanation, not a small number. | A tiny break-even would imply the strategy works if you keep it small. It does not — the spread alone beats the signal at every size. |

## Milestone 4 — vectorised backtest engine

| # | Ambiguity | Choice made | Why it is the conservative one |
| --- | --- | --- | --- |
| 41 | The spec's rebalance convention is "signal on close of T, traded at T+1 open or VWAP, configurable". | **`NEXT_OPEN` is the default**; `NEXT_CLOSE` is offered; true VWAP is **not**, because free data has no intraday path and a fake VWAP would be the most flattering fill of the three. | The open of T+1 is the first price anyone could actually transact at given a signal from T's close. Offering a VWAP we cannot compute would invite its use precisely because it looks sophisticated. |
| 42 | Whether same-bar execution should exist at all. | It exists as `SAME_CLOSE`, refuses to construct without `acknowledge_look_ahead=True`, and stamps the result `contaminated`. | The red-team suite in Milestone 5 needs a strategy that cheats in a known way. Making it impossible would mean hand-rolling the bug in test code, where it would be less visible. |
| 43 | What the engine holds constant between rebalances. | **Shares**, so weights drift with returns. | Holding weights constant implies trading every day to maintain them — free in a backtest, expensive in reality. The difference is exactly the turnover this platform exists to charge for. |
| 44 | Default delisting return. | **−30%**, applied to the *execution* price on the instrument's final bar, not only to the mark. | Free data supplies none, and treating the last observed price as a final settlement assumes the holder got out whole. Applying it to the mark alone closes the position at the last good price and records no loss at all — a bug this milestone actually had, and one that would have been invisible in the equity curve. |
| 45 | Forward-fill limit. | **5 bars**, configurable, with `StalenessPolicy.strict()` for none. Beyond the limit the position is liquidated. | Unlimited forward-filling turns a halted instrument into a position with no volatility and no drawdown — and a risk-parity weighting then allocates *more* to it, precisely because it looks calm. |
| 46 | Day count for borrow and financing inside the engine. | **Calendar days**, so a weekend accrues. | A 252-day convention understates financing by nearly a third, which for a levered carry strategy is the whole edge. |
| 47 | Whether cash earns interest. | **No.** | Assuming it did hands every low-exposure strategy a free return stream it never earned, and the flattery scales with the rate environment. |
| 48 | Splits. | Not modelled. The engine consumes an already-split-adjusted price series and requires dividends on the **same** adjustment basis. | That is what the data layer produces, and Yahoo's dividend amounts are split-adjusted consistently with its prices. The engine cannot detect a basis mismatch and says so rather than pretending to. |
| 49 | How the accounting identity is checked. | Two **independent** computations per bar — balance sheet (`cash + Σ shares·price`) and income statement (`prior equity + P&L − costs`) — reconciled to a cent, with a breach raising. | Checking equity against the formula that produced it asserts nothing. The two routes share no arithmetic, so a bug in either shows up as a gap. |
| 50 | Reporting a Sharpe ratio before the deflation machinery exists. | The field is named `sharpe_undeflated`, never `sharpe`, and every summary carries `[UNDEFLATED]`. | Spec section 13 forbids reporting a Sharpe without its trial count. Making the raw number impossible to read as anything else is more robust than remembering to caveat it. |
| 51 | Panel timing and run config could disagree silently. | The engine **refuses** to run a panel built for one convention under a config declaring another. | The panel decides the fill price and the config decides the lag; a mismatch reports a convention the run did not use, and for `SAME_CLOSE` would mislabel a contaminated run as clean. |

## Milestone 5 — validation

| # | Ambiguity | Choice made | Why it is the conservative one |
| --- | --- | --- | --- |
| 52 | How the trial count reaches the deflated Sharpe. | **Automatically.** Every `VectorisedBacktest.run` records itself, and the count is of *distinct configurations* per family. Opting out of recording also opts out of getting a deflated Sharpe. | Spec section 7: manual honesty about trial counts does not work. There is deliberately no way to search quietly and still quote a deflated number. |
| 53 | Whether re-running an identical configuration is a new trial. | **No** — the search did not widen. Changing any parameter **is**. | A count that grows when you re-run the same thing is noise; one that ignores a changed parameter is a lie. |
| 54 | Trial Sharpe variance when a sweep is near-identical. | Floored at **1/T**, the sampling variance of a Sharpe estimate under the null. | Without the floor a sweep of similar configurations shows almost no dispersion, the expected maximum collapses, and forty trials deflate as though they were one — which is exactly the search pattern most likely to overfit. |
| 55 | What `minimum_backtest_length` measures against. | The expected maximum of *N standard normals*, i.e. in units of the Sharpe estimator's own standard error. | Scaling it by the observed trial spread is circular: that spread depends on the sample length being solved for. The self-contained form reproduces the published result that a 0.5 Sharpe after a hundred tries needs about thirty years. |
| 56 | Haircut defaults. | 12% in-sample selection and 40% post-publication decay, composing to **×0.53**. | That is the spec's own working prior that live Sharpe is about half the backtest Sharpe, and a test asserts the composition so neither default can drift without the prior being re-examined. |
| 57 | The deflation threshold. | 0.95, conventional and arbitrary in the usual way. | What is not arbitrary is that most backtests fail it. The threshold is exposed as `survives_deflation` so it can be argued with rather than buried. |
| 58 | Purging when combinatorial test groups are far apart. | Per **contiguous block**, not across the span from first to last test index. | Treating groups 0 and 5 as one window purges the entire sample between them. That silently deletes almost all the training data and surfaces much later as an inexplicable failure. |
| 59 | Whether the CPCV path spread is evidence when nothing is refitted. | **No**, and the API documents it: running CPCV over a fixed return series produces identical paths. | Reporting that spread as robustness would be circular. `cpcv_path_returns` takes a `fit_predict` callable precisely so the refitting is explicit. |
| 60 | Whether any statistic here detects survivorship bias. | **None of them do**, and the red-team suite asserts it. | Deflation corrects for how hard you searched; nothing corrects for a universe that excluded the failures. A clean validation report is not evidence that the universe was clean, and pretending otherwise would be the most dangerous thing this package could do. |

## Milestone 6 — Tier 1 signals

| # | Ambiguity | Choice made | Why it is the conservative one |
| --- | --- | --- | --- |
| 61 | What a signal returns. | A **score**, never a weight. Portfolio construction owns the conversion. | A signal that sizes its own positions has taken over risk management, and two such signals cannot be combined without one of them being wrong. |
| 62 | How signals read data. | Only through a point-in-time `Snapshot`, one per rebalance date. | Computing the whole panel in one pass would be much faster and would make look-ahead a matter of author discipline rather than of structure. A signal that sees one snapshot physically cannot see past it. |
| 63 | Trend lookbacks. | 21/63/252 bars, blended. | Picking a single lookback is unstable *and* is the first step of a parameter search nobody counts. The blend is asserted to sit between the singles. |
| 64 | Where volatility scaling belongs. | Per-instrument scaling is part of the **signal** (comparing a move to the volatility it was earned through). Portfolio-level volatility targeting is a separate overlay. | Without the first, the signal is dominated by whatever is most volatile rather than what is most trending. The second needs the whole book and so cannot live in a signal. |
| 65 | Sign of the crypto carry score. | The carry from a **long**, i.e. the negative of the funding rate. | Getting this backwards produces a strategy that systematically takes the losing side of every carry, and backtests as a consistent, confident, slow loss. Asserted by test in both directions. |
| 66 | Funding annualisation. | From the **observed** interval, not an assumed 8 hours. | The interval has changed over time and differs per contract; annualising an eight-hour rate as daily overstates the carry threefold. |
| 67 | How perpetual funding reaches the backtest. | As the `dividend` column — a periodic per-share cash flow, negative for longs when funding is positive. | It is exactly what that column already models, so no engine change was needed, and the carry appears in the P&L rather than being described in a comment. |
| 68 | Missing fundamentals line items. | `None`, never zero. | A missing SG&A treated as zero makes a company look more profitable than it is, and the filers with missing items are systematically the small, badly reported ones — so the error is a size tilt, not noise. Zero is kept distinct from absent. |
| 69 | Signals whose data the free catalogue cannot supply. | Implemented, declared, and made to **raise** with the reason and the milestone that will fix it. | An empty cross-section looks exactly like a signal with no view, and a strategy built on one would trade nothing while appearing to work. |
| 70 | The spec's ">0.9 correlation with Ken French UMD" test. | Implemented as machinery with an explicit `Comparability` grade. The 0.9 threshold applies only at `SAME_UNIVERSE`. | A factor on fourteen ETFs is not a noisy version of one on three thousand stocks; applying the threshold there would be superstition. Measured anyway: **+0.539**, which is the right sign and magnitude for a related universe. The real test waits on a stock universe (Milestone 9). |
| 71 | Volatility targeting's status. | Risk management, not alpha, and leverage is capped. | Spec section 4: the factor-level "volatility-managed alpha" result is contested and largely does not survive costs. A volatility target with no cap becomes a leverage machine in quiet markets, which is precisely when quiet ends. |
| 72 | `RebalanceFrequency` living in the backtest layer. | Moved to `quantlab.conventions`, outside the layer stack. | Signals declare their own cadence, and reaching up into the engine to say so violates the downward-only rule — which the import-graph test caught. |

## Milestone 7 — portfolio construction and risk

| # | Ambiguity | Choice made | Why it is the conservative one |
| --- | --- | --- | --- |
| 73 | Default covariance shrinkage target. | **Constant correlation**, not identity. | Identity assumes uncorrelated assets with equal variance, which is so wrong for a real universe that shrinking toward it does not help. On a 40-asset, 80-observation factor panel the constant-correlation target removes 21% of the sample covariance error while the identity target removes none — the identity-shrunk estimate is about 6% *worse* than the unshrunk sample. A default that makes the answer worse is not a default. |
| 74 | Whether the Ledoit-Wolf `rho` term is worth computing. | **Yes**, computed in full for the constant-correlation target. | Most implementations drop it because the target is treated as fixed. It is not: it is estimated from the same data, and ignoring that over-shrinks. |
| 75 | Expected returns in `portfolio build --method mean-variance`. | **A flat prior of zero**, never the sample mean. | Sample means are noisy enough that optimising on them reliably produces a worse portfolio than equal weighting. Zero makes the command a minimum-variance solver and says so, rather than presenting an unstable estimate as a view. |
| 76 | An infeasible constraint set. | **Raises**, naming the arithmetic. `Constraints.long_only()` caps positions at 10%, so eight names can reach only 80% of capital against a net target of 100%. | SLSQP reports "inequality constraints incompatible" and returns weights that look entirely plausible and violate the constraints. A wrong portfolio that answers is worse than no portfolio. |
| 77 | What a stop-loss measures its loss from. | The **peak since entry** (a trailing stop), with `basis="entry"` kept only for comparison. | Measured from the entry price, a position that has run up 300% must give all of it back before the stop fires — the control switches itself off exactly on the long-held trend positions the cited result is about. On a driftless random walk it fires 6 times per thousand bars where a trailing stop fires 122. |
| 78 | Returns used for covariance, attribution and PCA in the CLI. | **Total returns** from `adj_close`, not price returns from `close`. | Dropping dividends removes the yield from every return, and in an attribution it reappears as alpha: SPY over five years attributes to −1.45%/yr (t = −2.3, "significant") on price returns and +0.02%/yr (t = 0.04) on total returns. A short book would show the same error as manufactured alpha. The cost is that `adj_close` is restated and therefore not point-in-time — acceptable for measuring realised exposure over a fixed historical window, and *not* acceptable in the backtest engine, which keeps using raw closes with corporate actions applied on their own dates. |
| 79 | Joining daily bars to daily factor series. | On the **calendar date**, explicitly, after truncating both timestamps. | A daily bar is stamped at its session close (20:00 UTC for a US listing) and a daily series at midnight, so an exact-instant join matches nothing at all. Aligning them positionally instead would appear to work while regressing one series against another shifted by every session either side is missing — spec section 13's hidden time-misalignment bug. |
| 80 | What PCA decomposes. | The **correlation** matrix, rescaled back into return units afterwards. | Maximising explained variance selects for the loudest asset. On the twelve-ETF universe, covariance PCA returns a first component loading +0.71 on a 41%-volatility oil fund and under 0.35 on everything else — an oil factor labelled "market". Standardised, PC1 loads −0.31 to −0.38 on every equity and credit name and 0.09 on oil. |
| 81 | Instruments with an incomplete history over a lookback window. | **Dropped, loudly**, never zero-padded. | Padding understates both the volatility and the correlation of whichever instruments have least data, which flatters exactly the positions that deserve least confidence. |
